# アクセス計測を有効にするための反映手順

やることは2つです。

- **A. Worker（データを受け取るプログラム）を更新する**
- **B. サイトの変更をアップロード（公開）する**

すでに用意したもの：

- `worker.js` … Workerの新しいコード
- Cloudflareに「senior-site-analytics」というデータベースを作成済み
- サイトのファイル（index.html、tokushoho.html、教材ページ2つ）に計測コードを追加済み

## A. Workerを更新する

> **【2026-08-14 更新】D1データベースをつなぐ作業（旧・手順5）は削除しました。**
> **もう設定済みだからです。** `/page-stats` を開くと記録が返ってくることで確認できます
> （つながっていなければエラーになります）。2回目以降は下の3ステップだけで済みます。
>
> また、Cloudflareの画面が変わり、**バインディングは「設定」の中ではなく、
> 上のタブに独立した「バインディング」**として並ぶようになりました。
> 確認したいときはそこを開くと `DB` → `senior-site-analytics` が見えます。

1. ブラウザで https://dash.cloudflare.com を開き、ログインする
2. 左メニューから「Workers & Pages」→ 一覧から「roy-senior-site-api」をクリックする
3. **画面の右上にある「コードを編集する（Edit code）」を押す**
4. 今表示されているコードを**全部**選択して削除し、
   同じフォルダにある `worker.js` の中身を全部コピーして貼り付ける
5. 右上の「デプロイ（Deploy）」ボタンを押す

これでWorkerの更新は完了です。

### うまくいったか確かめる

ブラウザで次のURLを開いて、記録が返ってくればOKです（真っ白やエラーなら失敗）。

```
https://roy-senior-site-api.roy-s1105.workers.dev/page-stats
```

## B. サイトの変更を公開する

このサイトはGitHubに置いたものが **GitHub Pages** としてそのまま公開されます（`https://roys1105.github.io/roys-senior-it/`）。いつもサイトを更新するときと同じ方法で、変更をアップロード（git push など）してください。

※以前ここに「Cloudflare Pages に自動公開される」と書いてありましたが、**誤りでした**（2026-08-15 修正）。Cloudflare で動いているのは、お問い合わせフォームとアクセス集計の Worker だけです。

普段GitHub Desktopや他のツールを使っている場合は、いつもの手順で「変更をコミットしてアップロード」してもらえれば、自動的にサイトへ反映されます。やり方が分からない場合は、いつでも聞いてください。一緒に進めます。

## 確認方法

公開が終わったら、実際にサイト（トップページや教材ページ）を開いてみてください。数分後、作成したライブアーティファクト「シニアサイト アクセス状況」を開くと、訪問数・教材ページ閲覧数が表示されるようになります。

### `?from=` が記録されるかの確認（2026-08-14 追加）

**AとBの両方が終わってから**、この順でやってください。片方だけでは記録されません。

1. ブラウザで、末尾に `?from=test-001` を付けたURLを開く

```
https://roys1105.github.io/roys-senior-it/?from=test-001
```

2. 1〜2分待ってから、次のURLを開く

```
https://roy-senior-site-api.roy-s1105.workers.dev/page-stats
```

3. 結果の中に、こういう行があれば**成功**です。

```json
{"date":"2026-08-14","type":"ref","page":"test-001","count":1}
```

`type` が `ref` の行が流入元です。見つからないときは、AとBのどちらかが未反映です。

**この確認ができてから、note の第0クール（熱中症の3本）を公開してください。**
順序が逆だと、最初の3本ぶんの流入だけ取り逃します。
